# Filament make-resources — Design

Date: 2026-07-29  
Status: approved for planning (pending user review of this file)

## Goal

Provide an Artisan command that generates Filament resource scaffolding (Resource, Table, Form schema, pages) for Eloquent models in a chosen domain, while making Laraplate Filament traits the default output of Filament’s own make generators via a permanent, intentional container rebind.

## Non-goals (this iteration)

- Custom column/field rules from `fillable` ∪ `casts` ∪ `attributes` − `hidden` (deferred; Filament’s current `--generate` / schema behaviour is accepted for now).
- Completing full `HasForm` auto-build behaviour beyond wiring the trait when useful.
- Generating Filament code for Laraplate-owned official modules via the new command (blocked by design).
- Changing Coolsam/Filament upstream packages.

## Decisions locked

| Topic | Decision |
|---|---|
| Command name | `filament:make-resources` |
| Module argument | Optional `{module?}`; default `App` |
| Official modules | Never generated by this command |
| Ownership flag | `laraplate_owned` in `module.json` (set **manually** on official modules; no stub / `module:make` change) |
| Ownership API | Helper `is_laraplate_owned_module()` + Nwidart `Module` macro `isLaraplateOwned()` (no dedicated service) |
| Ownership fallback | If `laraplate_owned` key absent → `composer.json` `name` matches `swolley/laraplate-*` |
| Explicit `laraplate_owned: false` | Not owned, even if composer name looks official |
| `App` | Not a module; never “owned”; always allowed as default target |
| Pivot models | Excluded via `models()` `$filter` (`Pivot` / `MorphPivot`); filter is required |
| Generator strategy | Permanent container rebind of Filament resource ClassGenerators |
| Trait injection | Yes, in rebound generators (phase 1) |
| Column/form body | Filament behaviour as-is for now; Laraplate metadata rules later |
| Trait selection | Resolved from generation target namespace (module Utils if present, else Core) |
| Existing files | Interactive overwrite prompt; `--no-interaction` → skip |
| App panel discovery | `AdminPanelProvider` discovers `app/Filament` resources/pages |

## Architecture

### 1. Module ownership

**Contract in `module.json` (official modules):**

```json
{
  "name": "Core",
  "laraplate_owned": true
}
```

**Resolution order** (`is_laraplate_owned_module(string $name): bool`):

1. If `$name === 'App'` → `false`.
2. Locate module path; if missing → `false`.
3. If `module.json` has key `laraplate_owned` → cast to bool and return.
4. Else read `composer.json` `name`; return true if string matching `swolley/laraplate-*`.
5. Otherwise → `false`.

**Macro** (registered from Core boot):

```php
Module::macro('isLaraplateOwned', fn (): bool => is_laraplate_owned_module($this->getName()));
```

**Filtering existing helpers:** do not add new boolean parameters to `modules()` / `models()`. Use the existing `$filter` callable, e.g. exclude owned modules when listing custom modules. Normalize `modules()` filter argument to the module **name** (`$class->getName()`) for predictable callbacks.

**Stub / `module:make`:** do **not** add `laraplate_owned` to Nwidart/Core stubs. Custom modules omit the key (or can set `false` by hand). Official modules: set `"laraplate_owned": true` manually in each `module.json` during implementation; composer `swolley/laraplate-*` remains the safety net if the flag is missing.

### 2. Permanent Filament generator rebind

Laraplate intentionally replaces Filament’s resource file generators so **all** `make:filament-resource` and `module:make:filament-resource` runs produce Laraplate-aware classes.

Bind (Core service provider, always — not scoped to the batch command):

- `ResourceClassGenerator` → Laraplate variant  
  - Extends `Coolsam\Modules\Resource` instead of bare Filament `Resource` when appropriate.
- `ResourceTableClassGenerator` → Laraplate variant  
  - Uses resolved `HasTable`; `configure()` delegates through `configureTable(...)`.  
  - Filament-generated column/action/filter body may still be passed into the `$columns` / related callbacks where that preserves Filament’s current behaviour.
- `ResourceFormSchemaClassGenerator` → Laraplate variant  
  - Uses resolved `HasForm` (currently a safe no-op until form auto-wiring is finished). Existing Form schema classes already call `self::configureForm($schema)` at the start of `configure()`.
- List page generator → add resolved `HasRecords`.
- Create/Edit (and View if generated) → keep Filament structure; only adjust imports/base if required for consistency.

Infolist generators: leave Filament default unless a later rule requires traits.

**Upgrade note:** constructor signatures of Filament generators may change; treat rebound classes as thin adapters and cover with smoke tests.

### 3. Trait resolver

Traits are chosen from **where files are generated**, not from a hardcoded CMS list.

```text
For target App:
  Modules\Core\Filament\Utils\{HasTable|HasRecords|HasForm}

For target module {Module}:
  candidate = Modules\{Module}\Filament\Utils\{Trait}
  if class_exists(candidate) → candidate
  else → Modules\Core\Filament\Utils\{Trait}
```

Current map (informational, not hardcoded logic):

| Target | HasTable | HasRecords | HasForm |
|---|---|---|---|
| App | Core | Core | Core |
| CMS | CMS | CMS | Core (no CMS HasForm) |
| ERP / AI / MES | Core | Core | Core |
| Custom module | Utils if present | same | same |

### 4. Command `filament:make-resources`

**Signature (conceptual):**

```text
filament:make-resources {module?}
```

**Flow:**

1. `$module = argument ?? 'App'` (normalize studly / `App`).
2. If `$module !== 'App'` and `is_laraplate_owned_module($module)` → error and exit failure.
3. Collect models:

   ```php
   models(
       onlyModule: $module,
       filter: static fn (string $class): bool =>
           ! is_a($class, \Illuminate\Database\Eloquent\Relations\Pivot::class, true)
           && ! is_a($class, \Illuminate\Database\Eloquent\Relations\MorphPivot::class, true),
   );
   ```

4. For each model, invoke existing makers with non-interactive options where possible:
   - `App` → `make:filament-resource`
   - else → `module:make:filament-resource` with `module` argument  
   Rebound generators supply Laraplate traits automatically.
5. Existing files: rely on Filament `checkForCollision` prompt (overwrite yes/no).  
   Under `--no-interaction`: **skip** existing files (do not abort the whole batch if one file exists — batch orchestration should continue to next model; per-resource Filament abort on decline must be handled so one skip does not stop the loop).
6. Summary: created / skipped / failed counts.

**Output locations:**

- `App` → `app/Filament/Resources/...`
- Custom module → `Modules/{Module}/app/Filament/Resources/...`

### 5. App panel discovery

`AdminPanelProvider` must discover App Filament classes (modules already discover via `ModuleFilamentPlugin`):

- `discoverResources(in: app_path('Filament/Resources'), for: 'App\\Filament\\Resources')`
- `discoverPages(in: app_path('Filament/Pages'), for: 'App\\Filament\\Pages')`

Exact paths/namespaces follow Filament/Coolsam conventions already used for modules.

Without this, App-generated resources would not appear in the admin panel.

## How existing makers behave (context)

- Filament `make:filament-resource` builds files via ClassGenerators (`app(Resource*Generator::class, …)`), not publishable Blade stubs for resources.
- `--generate` reads **database** columns, not Eloquent fillable/casts/hidden.
- Coolsam `module:make:filament-resource` extends the same command and only redirects path/namespace into a module.
- Collision already prompts for overwrite; decline throws `FailureCommandOutput` for that resource.

Rebind is the supported injection point for Laraplate behaviour without forking Filament.

## Testing

- Unit: ownership resolution (flag true/false, composer fallback, App, missing module).
- Unit: trait resolver (CMS → CMS traits; ERP → Core; App → Core; missing Utils → Core).
- Feature/console: command rejects owned module; accepts App; excludes Pivot classes from the model list.
- Smoke: rebound table/list generators emit the expected `use …HasTable` / `HasRecords` import for a target namespace.
- Optional: `AdminPanelProvider` discovery registration smoke.

## Follow-ups (out of scope now)

- Runtime / generator rules: build columns and form fields from fillable ∪ casts ∪ attributes − hidden, excluding trait-managed system fields (timestamps, soft deletes, validity, locks, activation, translations, order).
- Finish `HasForm` implementation.
- CMS-specific form trait if needed.
- Whether manual `make:filament-resource` should default `--generate` on/off for Laraplate DX.

## Implementation sketch (for planning)

1. Add `"laraplate_owned": true` manually to official module `module.json` files (no stub change).
2. Implement helper + macro + tests; fix `modules()` filter to receive module name.
3. Implement trait resolver + rebound ClassGenerators + provider bindings + smoke tests.
4. Add `filament:make-resources` command + tests.
5. Wire App `discoverResources` / `discoverPages` in `AdminPanelProvider`.
6. Document command + ownership flag in Core RAG / README as appropriate when behaviour ships.
